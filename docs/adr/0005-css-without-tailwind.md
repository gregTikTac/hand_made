# ADR-0005: Стили — дизайн-токены и кастомный CSS вместо Tailwind

- Статус: accepted
- Дата: 2026-10-30
- Уточняет: ADR-0001 (в части Tailwind)

## Контекст
ADR-0001 предполагал Tailwind (standalone CLI). На этапе 0 дизайн-система реализована как CSS-переменные (`tokens.css`) и набор компонентов (`components.css`), макеты утверждаются именно в таком виде. На этапе 1 шаблоны Django подключили эти файлы напрямую (`static/css/`). Перенос на Tailwind означал бы повторную вёрстку всех макетов без выигрыша для пользователя.

## Варианты
1. Перейти на Tailwind (standalone CLI): утилитарные классы, purge, дополнительный шаг сборки и бинарник в образе.
2. Оставить токены + кастомный CSS (как в макетах), без шага сборки.

## Решение
Вариант 2. CSS из `docs/design/` является источником истины для `static/css/`; отдельного шага сборки нет. Объём CSS небольшой (десятки КБ), сжатие и хэширование — WhiteNoise (`CompressedManifestStaticFilesStorage`). Tailwind-бинарник и цель `make tailwind` удалены.

## Последствия
- Проще: нет скачивания бинарников в Dockerfile, нет шага сборки CSS, макеты совпадают с шаблонами 1:1.
- Сложнее: новые компоненты пишутся вручную в `components.css` по токенам; изменения токенов нужно синхронизировать между `docs/design/` и `static/css/`.
- Вернуться к Tailwind можно новым ADR, если объём стилей станет неудобным.
