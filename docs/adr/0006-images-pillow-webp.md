# ADR-0006: Адаптивные изображения — webp-варианты через Pillow, без imagekit/sorl

- Статус: accepted
- Дата: 2026-10-30
- Уточняет: ARCHITECTURE §1 (изображения) и §10 (производительность)

## Контекст
ARCHITECTURE предлагал `django-imagekit` или `sorl-thumbnail` для webp в нескольких размерах (360/720/1080). `.clinerules`: новые зависимости — только с обоснованием. Pillow уже в проекте (ImageField). Фото загружает одна автор через админку, объём небольшой (80+ товаров × 5–10 фото).

## Варианты
1. `django-imagekit` / `sorl-thumbnail`: готовые кэши и шаблонные теги, но новая зависимость, свои миграции/кэш-ключи и отдельная логика очистки в S3.
2. Свои функции на Pillow: генерация при загрузке (`catalog/images.py`), имена производных детерминированы (`<имя файла>.<ширина>.webp`).

## Решение
Вариант 2. При сохранении `ProductImage` создаются webp-варианты шириной 360/720/1080 (без увеличения: ширина ограничена оригиналом). Оригинал остаётся как fallback (`<img src>`), варианты — в `<source type="image/webp" srcset>`. Размеры `width`/`height` сохраняются в БД (нет сдвига вёрстки). Удаление файлов — через `post_delete` + `transaction.on_commit` (в том числе при каскаде и в S3).

## Последствия
- Нет новой зависимости; логика видна и покрыта тестами.
- Генерация синхронная при сохранении (до ~1 сек на фото). Если массовый импорт станет медленным — вынести в Celery-задачу (идемпотентную) на этапе 8.
- Смена набора ширин требует перегенерации; для этого можно добавить команду `regenerate_images`.
