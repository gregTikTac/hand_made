## Этап 0. Дизайн-система и макеты
**Цель:** утверждённый заказчицей внешний вид.
- [ ] Промт 2 → токены (цвета, шрифты, отступы, радиусы) в `docs/design/tokens.css`
- [ ] HTML-макеты: главная, каталог (2 в ряд), карточка товара, корзина/чекаут (390px и 1280px)
- [ ] Состояния: hover, focus, disabled, loading, пустая корзина, ошибка, предзаказ + акция
- [ ] Согласование с заказчицей (скриншоты с телефона)

**DoD:** заказчица письменно подтвердила макеты; контраст AA проверен.

## Этап 1. Каркас
**Цель:** пустой сайт с админкой, запускаемый одной командой.
- [ ] Django-проект, приложения `core`, `catalog`, `orders`, `payments`, `delivery`, `promo`, `pages`
- [ ] Docker Compose: web, db, redis, worker, beat, mailpit; `.env.example`; Makefile
- [ ] ruff, pytest-django, pre-commit; CI (lint + tests)
- [ ] Django admin + тема; суперпользователь через команду
- [ ] Базовый шаблон, Tailwind (standalone CLI), токены, шапка, нижняя мобильная навигация, футер-заглушка
- [ ] Хранилища public/private (dev — MinIO или локальная FS)
- [ ] Staging на VPS

**DoD:** `make up` поднимает стек; `/admin/` работает; CI зелёный; заглушка в дизайне открывается на staging.

## Этап 2. Каталог
- [ ] Модели Product, ProductImage, ProductVideo, Category (миграции, индексы, ограничения)
- [ ] Админка товара: inline-фото с сортировкой, превью, фото материалов, PDF, видео-ссылки, подсказки
- [ ] Импорт из CSV (django-import-export) + команда импорта фото/PDF из папок по slug
- [ ] Список: сетка **2 в ряд** на всех ширинах, табы «Все / Комбо», «Показать ещё» (HTMX)
- [ ] Карточка товара: галерея (свайп), видео-embed, описание, «Необходимые материалы» фото, соцсети, поддержка
- [ ] webp/srcset
- [ ] `catalog/pricing.py` (base/compare_price) + тесты

**DoD:** 80+ товаров импортированы из CSV на dev; каталог и карточка совпадают с макетами на 390px; тесты зелёные.

## Этап 3. Корзина и гостевой чекаут
- [ ] Корзина в сессии (только product_id), HTMX добавление/удаление, счётчик в навигации
- [ ] Чекаут: email (с подтверждением), чекбоксы согласий (рассылка не предзаполнена)
- [ ] Создание Order + OrderItem со снимком цен; проверка «цена обновилась»
- [ ] Пустая корзина, ошибки валидации, rate limit

**DoD:** заказ создаётся в статусе `created` с корректным снимком; согласия сохранены с временем.

## Этап 4. Оплата, чеки, webhooks
- [ ] ADR-0002 принят (по ответу о СЗ/ИП)
- [ ] Интерфейс `PaymentProvider` + адаптер выбранного провайдера
- [ ] Создание платежа с idempotence key, redirect, страницы успеха/ошибки
- [ ] Webhook: подпись/IP, идемпотентность, state machine, сверка суммы
- [ ] Чеки 54-ФЗ (через провайдера или «Мой налог» — по ADR)
- [ ] Истечение неоплаченных заказов (beat)
- [ ] Тесты: повтор webhook, неверная подпись, неверная сумма, гонка

**DoD:** тестовая оплата в sandbox → `paid`; повтор webhook безопасен; чек формируется.

## Этап 5. Выдача файлов и email
- [ ] DownloadLink (хеш токена, TTL, лимит), `/d/<token>/` → presigned URL
- [ ] Email-провайдер, SPF/DKIM/DMARC, шаблоны писем
- [ ] Celery-задачи с ретраями, EmailLog (dedup_key)
- [ ] Повторная отправка: админка + форма «Не пришло письмо?»
- [ ] (опц.) водяной знак в PDF

**DoD:** письмо после тестовой оплаты приходит в Gmail/Яндекс/Mail.ru не в спам; ссылка работает N раз и истекает.

## Этап 6. Акции, предзаказы, комбо
- [ ] DiscountCampaign + админ-действие «Скидка на всё» (процент, даты)
- [ ] `pricing.py`: кампания + предзаказ; тесты по таблице ARCHITECTURE §3
- [ ] Бейджи «−30%», «Предзаказ», дата отправки, баннер акции
- [ ] PreorderRelease: жизненный цикл (beat), письмо «файл придёт…», кнопка «Выпустить», массовая рассылка, отчёт
- [ ] Комбо: ComboItem, выдача PDF входящих товаров

**DoD:** акция включается одним действием и выключается по дате; сквозной тест предзаказа (оплата → релиз → письмо) зелёный.

## Этап 7. Контент и юр.страницы
- [ ] Page + SiteSettings в админке; «Об авторе» (фото + текст)
- [ ] Оферта, политика, согласия, реквизиты; футер с соцсетями и поддержкой
- [ ] Главная: hero, «как это работает», популярные, блок об авторе

**DoD:** все ссылки футера ведут на заполненные страницы; заказчица меняет тексты сама.

## Этап 8. Тесты, безопасность, производительность, SEO
- [ ] Покрытие pricing / orders / payments / delivery ≥ 90%
- [ ] `manage.py check --deploy`, 2FA, rate limits, заголовки безопасности
- [ ] Lighthouse mobile ≥ 90, кэширование
- [ ] sitemap, robots, OG, schema.org, Метрика

**DoD:** чек-листы пройдены, отчёт Lighthouse приложен.

## Этап 9. Деплой, наполнение, передача
- [ ] Prod на VPS в РФ, TLS, бэкапы + проверка восстановления, мониторинг
- [ ] Импорт реального контента, проверка карточек заказчицей
- [ ] Боевой тестовый платёж + возврат
- [ ] `docs/admin-guide.md` + короткие видео: товар, акция, предзаказ, повторная отправка
- [ ] Передача доступов, договорённость о поддержке

**DoD:** реальная покупка прошла end-to-end; заказчица сама добавила товар и запустила акцию.
